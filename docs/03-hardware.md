# 硬件：接线、供电、仪器

> 引脚以 NUCLEO-F446RE 板上的 Arduino 丝印（D0～D15 / A0～A5）为准。动手前用万用表通断档或对照 UM1724 确认一次——**丝印比记忆可靠**。
> 本文件的引脚分配沿用原 `wiring.md`（已核对与 F446 数据手册一致），补充了供电预算、仪器接入点与电流实测步骤。

### 蓝牙 DX-BT24（USART1）

| 模块引脚 | 接 Nucleo | 说明 |
|---|---|---|
| VCC | 5V（以模块手册为准） | 模块板载 LDO |
| GND | GND | |
| TXD | PA10 (D2) | 模块发 → MCU 收（USART1_RX） |
| RXD | PA9 (D8) | 模块收 → MCU 发（USART1_TX） |
| STATE | PB0 (A3) | 可选，连接状态指示 |

**TX/RX 必须交叉**——这是最高频的接线错误，没有之一。

**电平必测**：上电后先不接 STM32，用万用表量模块 TXD 的空闲电平。
- ≈3.3V → 直连；
- ≈5.0V → 串 1kΩ + 2kΩ 分压到 3.3V，或加电平转换。**F446 多数引脚不耐 5V，别直灌。**

### 按键 ×3

一端接引脚，一端接 GND；软件开内部上拉（`GPIO_PULLUP`），按下读低。20ms 消抖。

### 蜂鸣器

```
PB10 (D6) ──[1kΩ]── S8050 基极(B)
                    集电极(C) ── 蜂鸣器(−)
                    发射极(E) ── GND
3.3V ──────────────────────── 蜂鸣器(+)
```

有源蜂鸣器给电就响，反接不响（不会烧，但你会查半天）。判断有源/无源：有源标注电压（3V/5V），无源只标频率。

## 2. 供电预算（原文档缺失）

NUCLEO 的 3.3V 由 USB 5V 经板载 LDO 得到，给扩展排针供电的能力有限。粗略预算：

| 负载 | 典型电流 | 峰值 |
|---|---|---|
| ST7789 逻辑 | < 10 mA | 20 mA |
| 屏背光（BL 接 3.3V 常亮） | 20～40 mA | 60 mA |
| DX-BT24 | 5～10 mA | 15 mA（广播/连接瞬间） |
| 蜂鸣器（经三极管，取自 3.3V） | 15～30 mA | 30 mA |
| **合计** | **≈ 50～90 mA** | **≈ 130 mA** |

结论：在 LDO 能力范围内，但**蜂鸣器响的瞬间仍是最容易掉压的时刻**。

**实测步骤（M1 就做一次，10 分钟）**：
1. USB 串一个电流表（或用几十块的 USB 电压电流表），记录"只插板子"的基线电流；
2. 接屏 → 记增量；再让蜂鸣器持续响 → 记峰值；
3. 若峰值超过 200mA 或电压跌到 3.1V 以下，把背光改接 5V 侧串限流电阻（先确认屏的 BL 引脚耐压）。

> 这个表本身是面试素材：说明你会给硬件做预算，而不是"接上能跑就行"。

## 3. 上电顺序（不许跳）

1. 只插 USB，不接任何外设，确认板子与 VCP 正常；
2. 量 3.3V 排针（≈3.3V）与 5V 排针（≈5.0V）；
3. 接屏，上电看背光；
4. 最后接蓝牙。

**不要一次全部插上再上电。** 万一短路，你会不知道是谁烧的，而且你会开始怀疑自己的代码。

## 4. 仪器与接入点

| 仪器 | 用途 | 接入点 |
|---|---|---|
| 万用表 | 通断/电压/电流 | 见 §2、§1 电平确认 |
| 8 通道逻辑分析仪（¥25～40，配 PulseView） | SPI 时序、单帧刷屏耗时、UART 波形 | CH0=CS、CH1=SCK、CH2=MOSI、CH3=UART_TX、CH4=调试 GPIO PA8(D7)（在代码里翻转，标记"开始刷新/结束刷新"） |
| USB 电流表（可选 ¥15） | 供电预算实测 | USB 线中间 |

**逻辑分析仪不是奢侈品**：简历上"单帧刷新 `___ms`、SPI 稳定 `___MHz`"这两个数字只能从它来。口头说"我用逻辑分析仪量的"和"大概几十毫秒"，在面试里是两个量级。

### 建议在代码里固定的两个测量点（M2 就加）

```c
/* PA8（丝印 D7）在引脚表里是空闲的，用它做测量标记，逻辑分析仪一接就能读 */
#define MEAS_HIGH()  HAL_GPIO_WritePin(GPIOA, GPIO_PIN_8, GPIO_PIN_SET)
#define MEAS_LOW()   HAL_GPIO_WritePin(GPIOA, GPIO_PIN_8, GPIO_PIN_RESET)
```

- 刷一屏：`MEAS_HIGH(); st7789_fill_screen(...); MEAS_LOW();` → 脉宽即全屏耗时；
- 一帧解析：在 `proto_feed` 返回 `PROTO_OK` 时翻转一次 → 逻辑分析仪上可直接看 5Hz 周期与抖动。

## 5. 接线可靠性

| 现象 | 90% 的原因 |
|---|---|
| 花屏、雪花、偶发错位 | 杜邦线太长 / SPI 太快 / 地线没共好 |
| 全白无反应 | RST 或 DC 接错，或初始化序列不对 |
| 画面整体偏移一半 | ST7789 240×320 的 GRAM 偏移没设，改 `CASET/RASET` 起始行 |
| 颜色红蓝互换 | RGB565 字节序或 `MADCTL` 的 BGR 位 |
| 串口收到乱码 | 波特率不对 / 地线没共 / TX·RX 没交叉 |

**先换 10cm 短线，再谈调参。** 长线 + 30MHz 是新手的经典组合，排查它要花掉一整天。
