# 施工图：6 周从 0 行到可演示

> 起点：硬件已下单未到；协议核心已 PC 可跑（96 项测试全绿）；其余固件 0 行。
> 节奏假设：每天 6 小时，`D0` = 硬件到货日。理想工时 14～18 天，按新手 **×1.8 调试系数** ≈ 25～32 个工作日 ≈ 5～6.5 周。

---

## 1. 这个项目要交付什么（成功定义）

不是"做出一个 HUD"，而是**四件能被验证的事**：

| # | 要证明的能力 | 对应的可见证据 |
|---|---|---|
| 1 | 能在资源受限目标上写**可分层、可测试**的软件 | `tests/` 96 项全绿；`proto_feed()` 不依赖 HAL；换传输层（VCP→BLE）零改动 |
| 2 | 能读手册把外设**点亮并压出极限** | 屏幕三色→棋盘→SPI 上限实测值；UART DMA + 空闲中断收包 |
| 3 | 有**边界条件**意识 | 粘包/半帧/错帧/假帧头/断连/看门狗/队列覆盖策略，每一项都有对应用例 |
| 4 | 有**量化**工程习惯 | 8 项指标全部自己测出、方法可复现 |

缺任何一条，简历上的项目就只是"跟着教程抄了一遍"。

## 2. 架构（我的版本）

```
        ┌─────────────── ISR / DMA 上下文 ───────────────┐
UART ──▶│ DMA 收字节 → 空闲/半满中断 → 推入环形缓冲(256B) │  只搬字节，不做 CRC
        └───────────────────────┬───────────────────────┘
                                │  环形缓冲（覆盖最旧 + 计数）
        ┌───────────────────────▼───────────────────────┐
        │ comms 任务：取字节 → proto_feed() → 结构体     │  纯 C，host 可测
        └───────────────────────┬───────────────────────┘
                                │  最新值邮箱（不是消息流，满即覆盖）
        ┌───────────────────────▼───────────────────────┐
        │ ui 任务：lv_timer_handler + 状态→页面映射      │  只读结构体
        └───────────────────────────────────────────────┘
        ┌───────────────────────────────────────────────┐
        │ mon 任务：3s 断连判定 / 心跳 / 按键消抖 / 喂狗 │
        └───────────────────────────────────────────────┘
```

三条不可让步的约束：

1. **`firmware/proto/` 不许 include 任何 HAL/FreeRTOS 头文件。** 它能在 PC 上编译，是这个项目唯一"低成本高质量"的来源。
2. **中断里只搬字节。** CRC、状态机、UI 全部在任务上下文。
3. **导航状态是"最新值覆盖"语义，不是消息流。** 队列满时丢最旧的（UI 落后 2 帧没有意义），不要设计成"每帧必达"。

## 3. 里程碑

每个里程碑都有 **出口判据（过不了不许进下一步）** 和 **退路（过了时间就降级，不许硬扛）**。

### M0 · 仓库与工具链 · 0.5 天
- **做**：`git --version` 确认可用 → 配置 `user.name` / `user.email` → `git init` → 首次提交 → 推 GitHub public；CubeIDE 建工程（F446RE，HSE 8MHz→180MHz，生成 HAL）；`tests\run.ps1` 本地全绿；`docs/log.md` 建好。
  - 若 `git --version` 报 not found：本机 PATH 里有一条 `D:\15081\Git\cmd`，但该目录下并没有 `git.exe`（只剩 `usr\share`），是**失效条目**——重装 Git for Windows 或修 PATH，别去改项目文件。
- **出口**：仓库能 clone；`run.ps1` 输出 `ALL PASS`；CubeIDE 空工程能编译通过并烧进板子。
- **退路**：无（这一步没有技术风险，只有拖延风险）。

### M1 · 板级验收 · 0.5 天
- **做**：`docs/04-bringup.md` 的阶段 0 全过：VCP 识别、读型号、全片擦除、LD2 闪烁、`printf` 出中文、量 3.3V/5V、连跑 30min。
- **出口**：7 项全绿，**任一失败就地停下**——这是板子问题，不是你的问题。
- **退路**：换 USB 线 / 换 USB 口 / 重装 ST-Link 驱动；仍失败联系卖家，别自己焊。

### M2 · 屏幕点亮（裸机） · 2～3 天
- **做**：SPI1 **11.25MHz**（APB2=90MHz ÷8）软件 NSS；ST7789 初始化序列（`SLPOUT`→`COLMOD=0x55`→`MADCTL`→`INVON`→`DISPON`）；三纯色 → 全屏棋盘 → 240×320 全屏填充；按 **5.625 → 11.25 → 22.5 → 45MHz** 逐档提到花屏，记录稳定上限；断电重启 20 次。
- **出口**：棋盘无错位/无撕裂；颜色正确（红蓝反了改 `MADCTL` 的 BGR 位）；**记录 SPI 上限值**；记录全屏刷屏耗时（逻辑分析仪量 CS 低电平宽度或 GPIO 翻转）。
- **退路**：退到 5.625MHz、换 10cm 短线、共地；仍花屏改为分块发送并降低刷新率——**先亮起来，再谈快**。

### M3 · 协议链路打通（PC → 屏） · 2 天 ← 关键里程碑
- **做**：把 `firmware/proto/` 拖进 `Core/Src`；`HAL_UARTEx_ReceiveToIdle_DMA()` 收 USART2（板载 VCP，**不需要 USB-TTL**）；超循环里 `proto_feed()` → 屏上显示距离数字；`tools/sim_sender.py --port COMx --log` 灌帧并同时看板子回显。
- **出口**（照 `04-bringup.md` 阶段 3 的 8 项）：十六进制手发一帧能变 → 5Hz 连续发送平滑 → 错 CRC 被丢弃且不影响下一帧 → 半帧超时恢复 → 两帧粘连都解析 → 停止发送 3s 后提示断连。
- **退路**：先不画屏，用 `printf` 打印解析结果（`seq/turn/dist`），确认协议对；屏幕问题留给 M2 的余量。**协议与显示必须分开验证。**

### M4 · LVGL 两页界面 · 3～4 天
- **做**：LVGL 8.3 接入（`lv_port_disp` 用 240×40 双缓冲，`flush_cb` 里 `lv_disp_flush_ready()`）；导航页（转向符号 + 距离大数字 + 底部状态行）、状态页（车速/剩余里程/ETA/丢包率/帧计数）；按键翻页；**不做中文字库**（内置 symbol + 自绘箭头）。
- **出口**：两页可切换；单帧耗时 ≤ 40ms；RAM 占用记录（`arm-none-eabi-size`）；重启 20 次无花屏。
- **退路**：LVGL 移植卡超过 2 天 → 改用自绘（8 个方向矩形 + 7 段数字），保底能演示，简历改写"自研极简绘图层"。**但优先攻 LVGL**，它是简历关键词。

### M5 · RTOS 化 · 1.5 天
- **做**：CubeMX 开 FreeRTOS（CMSIS-RTOS v2），改成 3 任务 `comms(3)` / `ui(2)` / `mon(1)`；`comms→ui` 用最新值邮箱（`osMessageQueuePut` 覆盖策略或 `osMessageQueueGet` 前先清空）；IWDG 4s，`mon` 喂狗条件是 **comms 与 ui 的心跳计数都必须推进**。
- **出口**：`vTaskList` 打印各任务栈余量 ≥ 128B；人为 `while(1)` 卡死 `ui` 任务时 IWDG 能在 5s 内复位；5Hz 连续 10 分钟无卡顿。
- **退路**：RTOS 引发难定位问题时退回超循环，并在 README 写清"为什么最终没上 RTOS"——**这本身也是合格的工程判断**，面试可讲。

### M6 · 稳定性与量化 · 1.5 天
- **做**：拔模块电源/停发 3s 的断连提示、重连 2 帧恢复、连续 30min soak 统计丢包率（`seq` 跳变）、RAM/Flash 占用、端到端延迟（回显 RTT + 录像分段）。
- **出口**：`docs/06-metrics.md` 8 项填满，每项写明测量方法与仪器。
- **退路**：soak 减到 10min，但必须在文档注明"未达 30min"。

### M7 · 蓝牙全链路（stretch） · 2～3 天
- **做**：DX-BT24 先脱离 STM32 用 USB-TTL 调 AT 指令（9600，必须带 `\r\n`）→ nRF Connect 找 `0xFFE0/0xFFE1/0xFFE2` 截图 → 接回 STM32 的 USART1 → 手机发样例帧 → 屏响应。
- **出口**：手机发帧屏响应；拔模块电源屏提示断连而不死机；30min 丢包率。
- **退路**：直接跳过。简历降级为"PC 上位机模拟器全链路"，**不影响主体成立**。

### M8 · 交付 · 1 天
- **做**：README 填实测数字；接线图（draw.io/Fritzing 截图）；30s 演示视频（手机拍）；简历 3 条定稿；仓库打 tag `v1.0`。
- **出口**：陌生人能照 README 复现；视频里能看见"发帧 → 屏幕变化"。

## 4. 时间表与投递节奏

| 周 | 主线 | 并行 |
|---|---|---|
| W1 | M0 + M1 + M2 起步 | 硬件到货当天只做 M1，别急着接屏 |
| W2 | M2 收尾 + M3 打通 | **M3 完成即写第一版简历并开始投递**（约第 2 周末） |
| W3 | M4 界面 | 简历保持更新 |
| W4 | M5 RTOS + M6 指标 | 投递高峰期，面试安排优先于开发 |
| W5 | M7 蓝牙（可选） | 补面试问题准备 |
| W6 | M8 交付 + 缓冲 | 留一周吸收"期末/面试/硬件翻车"的冲击 |

**关键提醒**：投递不必等 M8。M3 打通时你已经有一个能演示、有测试、有量化雏形的项目，这足够拿到笔试面试；M4～M6 是让它在面试里从"加分项"变成"主谈项"。

## 5. 每天怎么干

- **一次只改一个变量**。改两处然后好了 = 没学到东西，下次还会坏。
- **40 分钟规则**：卡住 40 分钟立刻换策略（降时钟 / 分段打印 / 拆最小复现 / 换引脚）。硬扛到凌晨是新手最大的亏法。
- **收尾 15 分钟**：`git commit`（消息写"为什么"）+ `docs/log.md` 写 3 行（试了什么 / 结果 / 下一步）。
- **先能跑，再跑好**。每个里程碑都允许"丑陋地通过"，禁止"漂亮地卡住"。

## 6. 不许做的清单（防完美主义）

1. 不许为了"看起来高级"上 RTOS / 文件系统 / C++ / 自研 GUI 框架。
2. 不许做 PCB、外壳、防水、12V 供电。
3. 不许在测试没改的情况下改协议（先改 `tests/test_proto.c`，红了再改实现）。
4. 不许连续看教程超过 30 分钟不动手。
5. 不许在没有实测值的情况下往简历里填数字。
6. 不许等"全部做完"才开始投简历。

## 7. 风险表

| 风险 | 概率 | 影响 | 应对 |
|---|---|---|---|
| 硬件到货延迟/少件 | 中 | 阻塞 M1 起 | 先做 M0 + 协议测试 + 读手册；M3 可先用任意 UART 模块验证 |
| 屏是 5V 版本或引脚标注不同 | 中 | 可能烧 IO | 上电前量模块 VCC 与 TXD 电平；先 3.3V 供电试 |
| LVGL 移植超过 2 天 | 中 | 挤占 M5/M6 | M4 退路：自研极简绘图层，保底可演示 |
| RTOS 引入难定位的偶发卡死 | 中 | 影响稳定性指标 | M5 退路：回退超循环并写清理由 |
| 期末/面试打断 | 高 | 进度延后 | W6 是缓冲周，不加新功能 |
| 花屏反复出现 | 中 | 耗时间 | 10cm 短线 + 降频 + 共地 + 逻辑分析仪看波形，别靠猜 |
