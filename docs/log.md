## 11-17  屏幕一直白屏，烧录还反复失败

**现象**：接上屏幕后，烧录报 `ST-LINK error (DEV_TARGET_HELD_UNDER_RESET)`；拔掉所有屏幕线后能烧；重新接上又失败。后来即使接了线也报 `Mass erase operation failed`。

**排查过程**：
1. `STM32_Programmer_CLI -l` 能列出探针（SN 0671FF56…），Windows 里 `ST-Link Debug` 状态也是 OK → 排除驱动/线的问题
2. 用 `mode=HOTPLUG` 读 `0xE0042000` 得到 `0x10006421`（DEV_ID=0x421）→ **芯片本身是活的**，只是被按在复位里
3. 用万用表/逐个拔线定位：**屏幕的 GND 那根插到了 `NRST` 孔上**（丝印太小，和 GND 挨着）→ NRST 被拉低，MCU 永远在复位
4. 拔掉后能烧，但紧接着连续 5 次中断的擦除把 **Flash 控制器卡死**，报 `Mass erase failed`（option bytes 显示 RDP=0xAA、无写保护，说明不是保护位问题）
5. 解法：**按住蓝色 RESET 键再上电**，让芯片在复位态启动，Flash 控制器回到初始状态 → 擦除恢复正常
6. 最后**白屏**的根因是接线返工：模块 VCC 需要 **5V**（模块背面有稳压芯片），接 3.3V 时背光亮但屏内部电压不足、初始化命令收不进去

**结论**：
- `DEV_TARGET_HELD_UNDER_RESET` = NRST 被外部按住，八成是线插错
- 连续中断擦除后 `Mass erase failed` = Flash 控制器卡死，**不是保护位**，按住 RESET 上电即可解除
- 背光亮但纯白屏 = 屏没收到有效命令，优先查 VCC 电压（这类模块分 3.3V 版和 5V 版）和 SCL/SDA 是否接反

**下次**：接线前先确认模块丝印顺序和 VCC 版本；插线后先用通断档确认 GND 那根真的在 GND 上。

## 11-17  用 DWT 测刷新耗时（没有逻辑分析仪也能测）

**做法**：打开 `CoreDebug->DEMCR.TRCENA` 和 `DWT->CTRL.CYCCNTENA`，在 `st7789_fill()` 前后读 `DWT->CYCCNT` 做差，把周期数存进全局变量，再用 ST-Link 直接读 RAM 拿回来。

**结果**（SPI 11.25MHz，阻塞式 `HAL_SPI_Transmit`）：
- 全屏 240×320：**19,983,835 周期 = 111.02 ms**（理论传输 109.2 ms，效率 101.6%）
- 局部 240×40：2,501,154 周期 = **13.90 ms**（理论 13.7 ms，效率 101.8%）

**结论**：耗时几乎全部是 SPI 传输本身，驱动开销不到 2%。要提速度只能提 SPI 时钟或改 DMA。5Hz 刷新只需 13.9ms，裕量充足。
