# 上电验收：每一步都要能独立证伪

> 顺序执行，**全绿再进下一步**。跳步省下的半小时，后面会变成两天的排查。
> 每条都写了"失败了怎么办"——原清单只说了"应该怎样"，没说"不对时先怀疑什么"，而那才是实际耗时的地方。

---

## 阶段 0 · 板子到手（不接任何外设） ← M1

| # | 检查项 | 失败先怀疑 |
|---|---|---|
| 0.1 | 只插 USB，设备管理器出现 **STLink Virtual COM Port** | USB 线是纯充电线 / 驱动没装 / 换 USB 口 |
| 0.2 | CubeProgrammer 能连接，读出的型号是 `STM32F446` | 板子没供电 / 装了别的 ST-Link 驱动 |
| 0.3 | 全片擦除（`Full chip erase`）成功 | 目标芯片被读保护 → 先 `Option bytes` 解保护 |
| 0.4 | 烧一个 LED 闪烁程序，LD2 正常闪 | 时钟配置（HSE 8MHz）/ 下载后没复位 |
| 0.5 | 串口助手打开 VCP，`printf` 输出中英文正常 | 波特率 / 重定向 `_write` 没实现 / 中文编码 |
| 0.6 | 万用表量 3.3V ≈ 3.3V，5V ≈ 5.0V | LDO 或 USB 供电不足 |
| 0.7 | 连续通电 30 分钟不死机、USB 不掉线 | 换线；仍掉 → 板子问题 |

**任一失败就地停下。** 这是板子/工具链问题，不要带着它往下接外设，否则你会把板子问题和代码问题搅在一起。

## 阶段 1 · 屏幕点亮（裸机，不上 LVGL） ← M2

| # | 检查项 | 失败先怀疑 |
|---|---|---|
| 1.1 | 三纯色（红/绿/蓝）能刷满 | RST/DC 接错 → 初始化序列 → SPI 模式/位序（CPOL/CPHA、MSB first） |
| 1.2 | 全屏棋盘无错位、无边缘撕裂 | 线太长 / 时钟太快 / GND 没共 |
| 1.3 | 颜色正确 | 红蓝互换 = RGB565 字节序或 `MADCTL` BGR 位 |
| 1.4 | 画面没有整体偏移一半 | 240×320 的 GRAM 偏移没设，改 `CASET/RASET` 起始行列 |
| 1.5 | 从 11.25MHz 起，按 5.625 / 11.25 / 22.5 / 45 逐档提到花屏，记录**稳定上限** | 每次只加一档，记下哪一档开始花 |
| 1.6 | 断电重启 20 次都能正常显示 | 初始化时序里缺 delay / 复位不彻底 |

**记录两个数**：稳定 SPI 上限（MHz）、全屏刷屏耗时（逻辑分析仪）。

> 顺序很重要：**先三纯色，再棋盘，最后图片**。三纯色验证的是"通信对不对"，棋盘验证的是"寻址对不对"，图片验证的是"数据量大了会不会崩"。三件事分开证伪。

---

## 阶段 2 · 协议链路打通（**不碰蓝牙，不碰 LVGL**） ← M3 · 关键里程碑

PC 通过 **板载 VCP（USART2，PA2/PA3）** 直接灌帧，不需要 USB-TTL。

| # | 检查项 | 失败先怀疑 |
|---|---|---|
| 2.1 | `tests\run.ps1` 全绿（PC 侧 96 项） | 协议实现问题，先在这里解决，别上板 |
| 2.2 | 串口助手按十六进制手发一帧，屏上距离数字变化 | 没开接收 / DMA 没重新 arm / `proto_feed` 没被调用 |
| 2.3 | `sim_sender.py --port COMx --log`，5Hz 连续发送，箭头与距离平滑变化 | 帧被拒绝 → 打开 `n_drop_crc` 计数打印 |
| 2.4 | 故意发一帧错 CRC → 被丢弃且**不影响下一帧** | CRC 失败后清空了缓冲（看 `proto_parser.c` 的 `resync`） |
| 2.5 | 故意发半帧后停顿 → 超时后自动恢复 | 超时逻辑没进 `proto_feed` |
| 2.6 | 连续发两帧粘在一起 → 两帧都被解析 | 帧边界处理错（把整段当一帧） |
| 2.7 | 停止发送 3 秒 → 弹出断连提示 | 心跳计时用的是"收到字节"还是"解析成功"？必须是后者 |
| 2.8 | 重新发送 2 帧 → 恢复正常显示 | 恢复条件是否要求连续 2 帧 |

**这 8 项全过，通信层就算写对了。** 后面换蓝牙只是换物理层——因为 `proto_feed()` 只认字节，不认串口。

## 阶段 3 · LVGL 界面 ← M4

| # | 检查项 | 失败先怀疑 |
|---|---|---|
| 3.1 | `LV_COLOR_DEPTH=16`，`lv_port_disp` 注册成功 | `lv_conf.h` 没被包含 / 颜色格式 |
| 3.2 | 240×40 双缓冲（≈38.4KB），`flush_cb` 正常 | `lv_disp_flush_ready()` 没调 → 卡死或撕裂 |
| 3.3 | 导航页：转向符号 + 距离大数字 + 底部状态行 | 布局越界 / 字体缺字形 |
| 3.4 | 状态页：车速 / 剩余里程 / ETA / 丢包率 | 中文字段若显示方框 = 字体未含该字形（V1 不用中文可规避） |
| 3.5 | 按键翻页、蜂鸣提示 | 消抖窗口 / 按键电平极性 |
| 3.6 | 单帧刷新耗时 ≤40ms（逻辑分析仪） | 缓冲区太小导致 flush 次数多 / SPI 频率 |
| 3.7 | 断电重启 20 次无花屏、无死机 | 静态内存被写坏 / 栈溢出 |

## 阶段 6 · 蓝牙（stretch） ← M7

| # | 检查项 | 失败先怀疑 |
|---|---|---|
| 6.1 | 模块单独接 USB-TTL，串口 **9600 8N1** | 波特率 / 供电 |
| 6.2 | 发 `AT\r\n` 返回 `OK`（必须带回车换行） | 少了 `\r\n`——最常见的失败原因 |
| 6.3 | `AT+NAME=MotoHUD` 改名字 | AT 指令格式 |
| 6.4 | nRF Connect 能扫到并连接（配码 `123456`） | 手机蓝牙权限 |
| 6.5 | 找到服务 `0xFFE0`，特征 `0xFFE1`(通知) `0xFFE2`(写)，**截图存档** | 模块固件版本 |
| 6.6 | 手机往 `0xFFE2` 写样例帧，屏正确响应 | TX/RX 没交叉 / 电平不匹配 |
| 6.7 | 拔模块电源，屏提示断连而不死机 | 断连判定依赖"解析成功"而非"收到字节" |
